19. **收到需求「上传显示 cant read property of undefined」（14:45 前后）**：
    - 根因：`crypto.subtle` 仅在安全上下文（HTTPS / localhost）可用；经 LAN IP + HTTP 访问时
      `crypto.subtle` 为 undefined，`crypto.subtle.digest` 抛 "Cannot read properties of undefined"。
    - 修复：`public/app.js` 新增纯 JS `sha256Hex()` 实现（无 WebCrypto 依赖），
      `sha256()` 先尝试 `crypto.subtle`，不可用或失败时回退纯 JS。
    - 踩坑：纯 JS SHA-256 的填充长度公式在 56 字节输入时出错，正确写法
      `((msgLen + 72) >> 6) << 6`（预留 0x80 + 8 字节长度）；用已知向量
      （"" / "abc" / "The quick brown fox..."）及随机长度 0-300、65535/65536/65537、100000、300000 全部验证 PASS。
20. **server.js 静态文件响应加 `Cache-Control: no-cache`**：确保前端修复（如 app.js）能及时被浏览器重新拉取，
    不被陈旧缓存挡住。
21. **重启并端到端复测通过**：流式上传 200、分片 init/complete 200（sha256 校验通过）、Range 206、删除/清理正常。

## 关键决策 / 教训

- `server.js` 必须绑定 `0.0.0.0`（外部端口映射才能通）。
- 进程用 `setsid` 而非 nohup。
- `run_claude.js` / `start.sh` / `user_start.sh` 是平台文件，**不进 git**。
- git 目录属主 root，需要 `safe.directory` 配置。
- `/ask/claude` 的 base64 参数在日志里会被终端换行损坏，解码需先清理空格。
- 视频数据 `obs/*` 不入 git（`.gitignore` 覆盖，仅保留 `obs/.gitkeep`）。
- **`obs/` 是资产目录（用户真实视频），绝对禁止删除/清空/写入测试文件**：
  - 测试视频一律放 `/tmp`，禁止复制或上传到 `obs/`；
  - 即使测试上传 API（会写 `obs/`），测试结束必须**立即删除**测试文件；
  - 代码/脚本中没有任何删除 `obs/` 本身的逻辑（`rmSync` 只清 `obs/.uploads/<id>` 临时上传目录），保持如此。
- README.md 与 Readme.md 是硬链接（同一 inode），改一个即同步。
- **流式上传竞态**：`req.pipe(ws)` 后 `req.on('end')` 只代表请求体读完，不代表写盘完成；
  必须等 `ws.on('finish')` 再 `rename`/`stat`，否则 WSL2 overlayfs 上会 500 ENOENT。
- **pkill 匹配**：`pkill -f "node server.js"` 匹配不到 `node /abs/path/server.js`；
  应使用完整路径 `pkill -f "node ${PROJECT_DIR}/server.js"`（`user_start.sh` 已用此写法）。
- **WebCrypto 非安全上下文**：`crypto.subtle` 仅在 HTTPS / localhost 可用；LAN IP + HTTP 访问为 undefined，
  上传计算 sha256 必须带纯 JS 回退（`sha256Hex`），否则前端直接抛 "Cannot read properties of undefined"。
- **静态资源缓存**：前端文件响应加 `Cache-Control: no-cache`，保证修复后的 app.js 能被及时拉取，不被浏览器缓存挡住。
- **视频压缩**：浏览器播放流畅的关键不只是码率，`-movflags +faststart`（moov 前置）让 `<video>` 秒开；
  H.264 + yuv420p 保证全浏览器兼容；`-crf 23` 是体积/质量平衡点（0-51，越低质量越好体积越大）。
  ffmpeg 用 `child_process.spawn` 调用，不引入 npm 依赖；输出先写临时文件、更小才覆盖原文件，避免压缩失败损坏原视频。
