## 关键决策

- **服务端完整生成 HLS**（而非浏览器端转码）：ffmpeg 已装且支持 hls muxer；播放器直接拉 m3u8+ts，比直连大文件流畅、省流量
- **快速 remux vs 重编码**：ffprobe 探测首路 codec；`h264 + (aac|mp3)` → `-c copy` 无损快速切片；webm/vp9/opus 等 → `libx264 -crf 23 -preset medium -pix_fmt yuv420p -vf scale='min(1920,iw)':-2 -c:a aac -b:a 128k`
- **ffmpeg 在分段临时目录 cwd 运行**：m3u8 写相对分段名，路由自动解析到 `/hls/<name>/` 下
- **NATIVE_HLS 必须用 Safari UA 判定**：Chromium/Firefox/Edge 对 `canPlayType('application/vnd.apple.mpegurl')` 都返回 `'maybe'` 但**无法播放**；判定式 `_canNativeHls && /^((?!chrome|android|crios|fxios|edg).)*safari/i.test(navigator.userAgent)`，否则 Chromium 会误走原生 HLS 而黑屏（headless Chromium 实测踩坑）
- **前端只给 middle-copy 且在缓存窗口（diff≤1）的 item 挂 hls.js**：ghost 副本与窗口外保持直连 src，避免 3 副本 × 多视频重复拉分片
- **leader `startLoad()` / 非 leader `stopLoad()`**：避免后台视频狂拉分段浪费流量；`manageHls()` 在 `updateVideoCache()` 末尾与 `setPage()`/`finishSwipe()` 中调用
- **致命错误回退直连**：网络错误重试 1 次 → 媒体错误 `recoverMediaError()` 1 次 → 仍失败则 `destroy()` + `video.src = v.url` 直连 + `_hlsFallback` 防重挂循环
- **hlsReady 门控**：HLS 未生成时不阻塞播放，直接播 mp4/webm；`转HLS` 按钮 POST `/hls/<enc(name)>/generate` 后 `loadFeed()`
- **惰性生成**：`GET /hls/:name/index.m3u8` 时源在而分片缺失 → 自动生成（`obs/.hls` 被手动删除也能恢复）

## hls.js 缺失处理

- `public/vendor/hls.min.js` **必须存在**（`index.html` 在 app.js 前引入），否则非 Safari 浏览器无法走 HLS
- 缺失时 `window.Hls` undefined → `HAS_HLSJS = false` → 非 Safari 浏览器 `hlsCapable` 为 false → 直接播直连 mp4/webm，页面功能不受影响（只是不走 HLS）
- 注意：hls.min.js 的 UMD 会**无条件覆盖 `window.Hls`**，stub 测试需 `page.route("**/vendor/hls.min.js", lambda route: route.abort())` 防止真实 hls.js 覆盖 stub
